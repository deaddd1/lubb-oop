# Vision: Система управління рестораном (RestaurantSystem)

## 1. Короткий опис проблеми
Традиційне паперове або хаотичне ведення замовлень у ресторанах призводить до помилок персоналу, затримок у приготуванні страв та неможливості адекватно контролювати завантаженість столиків і фінансові потоки. Застосунок RestaurantSystem покликаний автоматизувати життєвий цикл замовлень, оптимізувати роботу офіціантів та надати менеджменту прозору аналітику.

## 2. Цільові користувачі
* Офіціанти — швидке створення замовлень, додавання страв, перевірка статусів.
* Кухарі — перегляд черги страв на приготування у реальному часі.
* Адміністратори / Менеджери — управління меню, бронювання столів, фінансові звіти.

## 3. Основні сценарії використання (Use Cases)
* Use Case 1: Оформлення нового замовлення для столика офіціантом та розрахунок вартості.
* Use Case 2: Зміна статусів замовлення (Прийнято -> Готується -> Подано -> Оплачено) з автоматичним логуванням часу.
* Use Case 3: Управління динамічним меню (додавання страв, призначення категорій, перевірка собівартості).

## 4. Нефункціональні вимоги
* Тестованість: Повне відокремлення бізнес-логіки від консолі та файлової системи дозволяє покрити сервіси тестами на 90%+.
* Надійність / Валідація: Неможливість переведення системи у некоректний стан (наприклад, замовлення від'ємної кількості страв або оплата вже закритого чека).
* Розширюваність: Архітектурні контракти дозволяють у майбутньому легко замінити консольний інтерфейс на Web API, а збереження у файли — на повноцінну БД SQL.

## 5. Обмеження першої ітерації (Lab 34)
На першій ітерації дані зберігаються виключно в оперативній пам'яті (In-Memory). Робота зі стійким збереженням (JSON файли), складні LINQ-звіти за місяць та динамічні патерни (наприклад, State для статусів) свідомо перенесені на наступну ітерацію (Lab 35).
